# Visual Hooks Library

Статус: концепция + первая серия из 12 работающих прототипов  
Дата: 28 июля 2026 года

Рабочая лаборатория доступна в проекте по маршруту `/visual-hooks`. Каждая сцена также имеет самостоятельный маршрут `/visual-hooks/{scene-slug}`.

## Идея

Создать самостоятельную библиотеку режиссируемых первых экранов — интерактивных visual hook scenes, которые вызывают у пользователя реакцию:

> «Я хочу, чтобы мой бренд выглядел и двигался так же выразительно».

На первом этапе библиотека не является частью конструктора Creatly. Это отдельная экспериментальная среда для создания, демонстрации и проверки сильных сочетаний:

- AI-визуала;
- генеративного видео;
- 3D-композиции;
- браузерной интерактивности;
- scroll- и cursor-driven motion;
- кинематографической хореографии;
- выразительной типографики.

Лучшие и наиболее устойчивые решения позднее можно адаптировать для Creatly.

## Что мы создаём

Не библиотеку шаблонов и не набор универсальных секций, а коллекцию авторских первых экранов.

Каждая сцена должна:

1. Работать как сильный статичный постер.
2. Иметь один доминирующий визуальный объект.
3. Создавать визуальную недосказанность.
4. Предлагать одну понятную интеракцию.
5. Давать выразительный motion-payoff.
6. Заканчиваться спокойным читаемым состоянием.
7. Вызывать желание использовать похожий приём для собственного бренда.

## Основная формула

```text
Concept
   ↓
Hero composition
   ↓
Visual tension
   ↓
User interaction
   ↓
Transformation
   ↓
Payoff
   ↓
Settle state / next scene
```

Или короче:

> Понятная композиция + один необычный объект + визуальный вопрос + управляемая трансформация.

## Принципы

### Один главный объект

У сцены должен быть один очевидный `attention anchor`:

- лицо или рука;
- продукт;
- 3D-персонаж;
- телефон или карточка;
- архитектурный объект;
- природная форма;
- стеклянный или металлический артефакт;
- портал;
- абстрактная скульптура.

Остальные элементы поддерживают его, но не конкурируют с ним.

### Один главный motion-приём

На первом экране не должно быть нескольких равносильных эффектов. Пользователь должен уметь описать механику одной фразой:

- «Курсор раскрывает другое состояние».
- «При скролле карточка становится новым миром».
- «Видео управляется прокруткой».
- «Объект собирается из частиц».
- «Фото превращается в 3D-материал».

### Движение должно объяснять идею

Motion не является украшением. Трансформация должна раскрывать:

- смысл продукта;
- изменение состояния;
- переход во времени;
- внутреннее устройство;
- обещание бренда;
- контраст «до/после»;
- связь между эмоциональным образом и функцией.

### Несколько скоростей

Сцена строится из слоёв с разной динамикой:

```text
Atmosphere       — очень медленно
Background       — медленно
Hero object      — главное движение
Interface        — быстро и точно
Cursor response  — мгновенно с инерцией
```

Хотя бы один слой остаётся неподвижным и сохраняет читаемость.

## Семейства сцен

### 1. Layered Reveal

Два или несколько визуальных состояний накладываются друг на друга.

Варианты:

- reveal за курсором;
- circular mask;
- draggable divider;
- object-shaped reveal;
- раскрытие внутри текста;
- проявление внутренней структуры;
- переход между сезонами, материалами или временными состояниями.

Смысловые пары:

- настоящее / будущее;
- природа / технология;
- физическое / цифровое;
- день / ночь;
- внешний вид / внутреннее устройство;
- сырой материал / готовый продукт;
- проблема / результат.

### 2. Cinematic Scrub

Пользователь управляет временем видео через scroll или drag.

```text
interaction progress → video.currentTime
```

Хороший scrub содержит три самостоятельных keyframe:

- `0%` — сильный стартовый постер;
- `50%` — максимальная трансформация;
- `100%` — чистая финальная композиция.

Применения:

- сборка продукта;
- изменение материала;
- движение камеры;
- раскрытие архитектуры;
- путешествие через пространство;
- переход между мирами;
- трансформация персонажа.

### 3. 3D Video Composition

AI-видео или 3D-рендер является центральным объектом сцены и композиционно объединяется с HTML-интерфейсом.

Приёмы:

- видео на чёрном или однотонном фоне;
- маскирование по силуэту;
- объект выходит за границы контейнера;
- объект перекрывает headline;
- HTML-подписи привязаны к частям объекта;
- CSS-свет продолжает освещение видео;
- интерфейс повторяет цвет и материал ролика;
- foreground скрывает границы видео.

### 4. Portal Object

Карточка, телефон, окно, линза или дверь содержит другую сцену, а затем становится новым viewport.

```text
Object inside hero
→ approach
→ expansion
→ fills viewport
→ becomes next scene
```

### 5. Object Continuity

Один визуальный объект проходит через несколько состояний:

- в hero — эмоциональный символ;
- далее — продукт;
- затем — схема или доказательство;
- в CTA — упрощённый знак.

Так страница становится одной историей, а не набором секций.

### 6. Mouse-reactive Depth

Несколько слоёв реагируют на курсор с разной амплитудой:

```text
background   × 0.02
middle       × 0.05
hero object  × 0.09
foreground   × 0.14
```

Дополнительные реакции:

- `rotateX` / `rotateY`;
- перемещение блика;
- изменение тени;
- локальный blur;
- смещение маски;
- инерция после остановки курсора.

### 7. Material Transformation

Объект меняет физическое или визуальное состояние:

- стекло → металл;
- камень → растение;
- продукт → частицы;
- ткань → жидкость;
- фотография → wireframe;
- физический предмет → цифровой двойник.

### 8. Product Theatre

Продукт представлен как главный герой рекламной сцены:

- макрокамера;
- выраженный студийный свет;
- контролируемое вращение;
- взаимодействие с руками или материалом;
- разбор на части;
- переход от эмоционального кадра к функциональному доказательству.

## Роль Higgsfield

Higgsfield используется как часть режиссёрского pipeline, а не как общая кнопка «сгенерировать красивое видео».

### До генерации

Для каждой сцены определяются:

- стартовый кадр;
- финальный кадр;
- главный объект;
- движение камеры;
- трансформация объекта;
- свободная зона для headline;
- освещение;
- длительность;
- формат цикла;
- пригодность для scrub;
- desktop- и mobile-crop.

### Набор ассетов

Одна сцена может включать:

1. Постер первого кадра.
2. Основной hero-объект.
3. Альтернативное состояние.
4. Видео трансформации.
5. Background plate.
6. Foreground plate.
7. Depth/mask asset.
8. Mobile-версию.

### Разделение ответственности

```text
Higgsfield
├── объект
├── камера
├── материал
├── свет
└── кинематографическая трансформация

Browser runtime
├── scroll scrub
├── cursor reveal
├── masks
├── parallax
├── typography
├── UI reaction
└── переход между сценами
```

Визуальная магия создаётся генерацией, а ощущение управления — браузером.

## Формат Scene Recipe

```ts
type VisualHookScene = {
  id: string
  title: string
  concept: string
  industry?: string

  hook: {
    anchor: string
    tension: string
    payoff: string
  }

  assets: {
    poster: MediaAsset
    background?: MediaAsset
    heroObject?: MediaAsset
    alternateState?: MediaAsset
    scrubVideo?: MediaAsset
    foreground?: MediaAsset
    mobile?: MediaAsset
  }

  interaction: {
    primary: "pointer" | "scroll" | "drag" | "autoplay"
    secondary?: "pointer" | "scroll" | "drag"
  }

  choreography: {
    intro: MotionCue[]
    anticipation: MotionCue[]
    transformation: MotionCue[]
    payoff: MotionCue[]
    settle: MotionCue[]
  }

  artDirection: {
    palette: string[]
    typography: string
    lighting: string
    camera: string
    material: string
  }

  performance: {
    preload: string[]
    mobileStrategy: string
    reducedMotionStrategy: string
  }
}
```


На первом этапе сцены являются самостоятельными мини-страницами и не обязаны соответствовать модели данных конструктора.

## Галерея на главной

Каждая карточка должна сама демонстрировать идею:

- сильный статичный постер до загрузки;
- autoplay только внутри viewport;
- короткий 6–10-секундный цикл;
- hover или pointer запускает основной приём;
- клик открывает полноэкранную сцену;
- название описывает эффект, а не отрасль;
- рядом кратко указан способ взаимодействия.

Примеры названий:

- `Portal Journey`;
- `Living Surface`;
- `Glass Passage`;
- `Product Bloom`;
- `Material Memory`;
- `Inside the Object`;
- `Future Underneath`;
- `World in a Card`.

## Первый набор

MVP состоит из 12 сцен:

1. Два cursor reveal.
2. Два cinematic scrub.
3. Два portal transition.
4. Два 3D/video hero.
5. Два material transformation.
6. Два layered parallax narrative.

Первая предварительная серия реализована:

1. `prism-veil` — cursor aperture между двумя состояниями автомобиля.
2. `orbit-memory` — управляемый прокруткой кинематографический объект.
3. `glass-passage` — расширяющийся портал в архитектурную сцену.
4. `signal-body` — синтетический персонаж, данные и крупная типографика.
5. `tactile-index` — физический hover-архив изображений.
6. `chromatic-twin` — разделение двух цветовых состояний курсором.
7. `bloom-protocol` — органическая многослойная pointer-система.
8. `monolith-type` — scroll-driven типографическая архитектура.
9. `quiet-machine` — product theatre с реактивным светом.
10. `horizon-fold` — ландшафтная parallax-история.
11. `inside-form` — material scan и reveal внутреннего устройства.
12. `soft-threshold` — атмосферный video-interface со стеклянным UI.

Текущие локальные ассеты являются временными. После восстановления Higgsfield визуалы заменяются через Scene Recipe без изменения основной интерактивной механики.

Для каждой сцены нужны:

- desktop-версия;
- mobile-версия;
- poster;
- полноэкранное demo;
- короткий preview loop;
- Scene Recipe;
- описание генерации ассетов;
- fallback для `prefers-reduced-motion`.

## Критерии качества

Сцена принимается в библиотеку, если:

- первый статичный кадр уже выглядит законченно;
- идея считывается без объяснения;
- главный объект определяется мгновенно;
- интеракция обнаруживается естественно;
- движение имеет смысловой payoff;
- headline и CTA остаются читаемыми;
- эффект работает без блокировки скролла;
- mobile-версия не зависит от hover;
- медиа не мешает первому meaningful paint;
- сцену хочется записать и показать отдельно.

## Что не делаем

- Не превращаем модуль в конструктор на первом этапе.
- Не пытаемся сделать любую сцену универсальной.
- Не добавляем 3D только ради 3D.
- Не используем несколько равносильных эффектов одновременно.
- Не начинаем с длинного logo intro.
- Не строим эффект, который полностью ломается без hover.
- Не используем генеративное видео как неуправляемый фон без связи с интерфейсом.
- Не копируем конкретные дизайны MotionSites; используем обнаруженные принципы для собственных концепций.

## Дальнейшее направление

Библиотека должна стать лабораторией визуальных хуков:

```text
AI art direction
      +
Higgsfield generation
      +
Browser interaction
      +
Motion choreography
      =
Desire to create
```

Первичная цель — выяснить, какие сцены сильнее всего вызывают желание «хочу такое для своего проекта». Интеграция с Creatly рассматривается только после появления набора доказанно сильных решений.
