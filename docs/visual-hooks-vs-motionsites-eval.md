# Честная оценка: Visual Hooks (50 сайтов) vs motionsites

Оценка сделана дважды независимо (я — визуально + по коду; Codex — по коду + teardown). **Выводы совпали.** Ниже — сведённая версия.

> Дисклеймер: выводы о Visual Hooks — факты из кода. Выводы о motionsites — наблюдения по превью-роликам (teardown); технология местами гипотеза, не подтверждённый исходник. Полнота реальных motionsites-сайтов не проверена (у нас только hero-превью).

## Вердикт

Наши 50 сайтов **пока не на уровне лучших motionsites по главному товарному обещанию — интерактивному «вау» первого экрана.** Большая часть коллекции — качественно арт-директированные **сайты-постеры**: видео/сгенерённый кадр помещён в одну из 8 сеток + reveal + hover, но не превращён в живую сцену, причинно связанную с действиями пользователя. Мы **сильнее в полноте лендинга, системности и ширине ниш.** Продавать это как «интерактив не хуже motionsites» сейчас — нечестно.

## Что подтверждает КОД (факты)

- В `PRO` — 34 сайта; `ProHero` — 9 вариантов (8 архетипов + legacy).
- **Ни один `ProHeroView` не использует `ShaderBg`/`ShaderImage`/`DepthParallax`/`ShaderReveal`.** Носители hero — обычные `<img>` и autoplay `<video>`.
  - hard-split / edge-arrival / portal-frame → зацикленное MP4.
  - product-theatre / type-collision / regime-shift → статичное изображение.
  - gallery-horizon → полоса изображений; index-stage → CSS-смена превью по hover.
- **«Regime shift» — не интерактивная смена режима**, а светлая сетка + статичный градиентный хвост `.ph-rg-dark`.
- `ShaderBg` — только в контентном блоке `cine`; `ShaderImage` — только в галереях ниже hero; `DepthParallax` — только в bespoke Ascension; `ShaderReveal` — только в bespoke Bloom/Vigil.
- Массовая механика = `IntersectionObserver`-reveal + autoplay-video + CSS-hover. Это анимация презентации, не драматургическая интерактивная сцена.

## ТОП-5 честных провалов

1. **Видео выдаётся за живой объект.** Движение внутри прямоугольного контейнера, независимо от пользователя. Объект не пересекает типографику, не выходит из рамки, не меняет ракурс, не становится навигацией. Это обрамлённое медиа.
2. **Нет причинной связи «я сделал → сцена ответила».** Autoplay/observer/hover происходят *рядом* с пользователем, а не *из-за* его содержательного действия. У motionsites курсор проявляет угрозу/поворачивает голову/меняет материал; scroll превращает карту в портал.
3. **8 архетипов скрывают новую шаблонность.** Силуэты разнообразнее, но формула одна: nav + headline + прямоугольное медиа + proof. Меняется геометрия контейнеров, не пространственная логика. `product-theatre` обещает театр объекта — код показывает картинку в скруглённом прямоугольнике с hover-scale.
4. **Три плана нарисованы внутри одного кадра.** Атмосферная перспектива на фото ≠ независимые background/midground/foreground с окклюзией и разной скоростью. Единственный `DepthParallax` — вне массовой системы.
5. **Композиция завершена до начала движения.** Hero сразу показывает всё; видео лишь поддерживает атмосферу. Нет визуального вопроса, который движение обязано разрешить → motion декоративен, а не необходим.

## ТОП-3, где мы сильнее / на уровне

1. **Полнота коммерческого лендинга — сильнее.** `ProBlock` = idea/cine/split/gallery/stats/quote/steps/editorial/cta: аргументация, proof, темп, завершение. Для реального запуска клиента — существенный плюс.
2. **Ширина ниш и производственная система — сильнее.** 34 ProSite + bespoke = масштабируемый каталог; палитры, 4 типо-личности, блоки, reduced-motion, WebGL-fallback — рабочий конструктор. motionsites — референс-коллекция; у нас свой переиспользуемый движок.
3. **Компетенция есть, но не перенесена.** Bloom/Vigil/Ascension/Ledger уже содержат правильные ингредиенты (сюрреал-концепт, shader-reveal, depth-map, cursor-response, сильный единичный объект). Проблема — это почти не попало в массовые 34 ProSite.

## Приоритетный план

1. **10 флагманов вместо равномерной полировки 50.** По разным категориям (product/fashion/hospitality/finance/wellness/craft/tech). Их показывать в сравнении с motionsites; остальные — как нишевую библиотеку.
2. **В `ProHero` добавить поле `payoff`, а не ещё layout.** 4–5 механик: `cursor-reveal`, `depth-gaze`, `scroll-assemble`, `portal-expand`, `type-occlusion`. Каждому флагману — ровно одна.
3. **`DepthParallax` в hero — первым.** Самый дешёвый заметный прирост глубины на нашем raw-WebGL. Higs Bot генерит depth-map (+ foreground mask). Курсор двигает воспринимаемую камеру, а не весь кадр.
4. **`ShaderReveal` из лаборатории в продуктовые hero.** Пары состояний: raw/polished, closed/open, dark/lit, dry/wet, sketch/product (клинок из окалины, карта из тумана, растение из мёртвого). Тогда интерактив несёт смысл продукта.
5. **Разрушить прямоугольник у `product-theatre`/`type-collision`.** Higs Bot отдаёт объект с чистым фоном/маской; объект — самостоятельный слой между задней и передней копией headline. Даже 2.5D даст больше «живого объекта», чем MP4 в карточке.
6. **Один reusable scroll-controller на CSS-variables.** Sticky hero, progress 0…1 → scale/translate/blur/clip-path/текст-слои. Three.js не нужен. Один непрерывный объект + один понятный переход, а не набор reveal.
7. **Типографику флагманов — как часть сцены.** Задний/передний слой headline + маска объекта + переменный scale/spacing по scroll = kinetic typography без нового 3D-стека.
8. **Жёсткий acceptance-тест hero:** флагман не принят, если после отключения autoplay он остаётся законченным постером. Действие пользователя должно раскрывать инфу/менять смысл; объект — минимум 2 независимых плана; payoff описывается одним глаголом (проявляет/собирает/вращает/открывает/переносит).

## Честная формулировка для продаж (сейчас)

Не «интерактивные сцены не хуже motionsites», а **«полноценные арт-директированные сайты с сильными cinematic hero»**. Право на первую формулировку появится после переноса `ShaderReveal`/`DepthParallax`/scroll-scrub хотя бы в 8–10 витринных hero.
